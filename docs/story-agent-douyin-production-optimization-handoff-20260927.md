日期：2026-09-27。用途：在新的对话继续开发。本文是建议路线与证据交接，不代表下列功能已经实现，也不授权付费调用、重新生成媒体、迁移运行库或覆盖旧版。

## 1. 总结与方向

下一阶段目标：让已有创作能力稳定地变成可制作、可接续、可验收的短视频，而不只让故事、提示词或机器报告通过。

主要归因不是“文案模型或视频模型二选一”：

1. 文案侧有节奏、重复内容与素材识别/质量误判问题。
2. 最大生产缺口是分镜动作在参考图适配与视频提示词转译中缩水，未形成可追踪的状态变化。
3. 同一原图独立生成多个片段再直接拼接，会使人物姿态和景别重置。
4. 本次本地视频配置的分辨率和稳定性限制真实存在，但没有同输入模型对照，不能给出模型责任百分比或保证换模型即可解决。
5. 成片已通过技术和抽帧检查，却仍暴露叙事/连续性问题；需要提高验收条件，不能简单增加一份“passed”报告。

产品方向是“内容规划 → 可拍分镜 → 参考素材 → 配音确认 → 视频生成/回片 → 连续性检查 → 统一时间轴 → 成片交付”。保留多类型创作能力，短视频只是一个制作配置，不把所有题材强制改成讲解或漫剧。

## 8. 开发路线：按小切片交付

### S01：先修制作需求被当作故事素材的质量误判（KB；推荐新对话首片）

真实反例：[了凡项目v2报告](/Users/wuyu/Desktop/china-culture-kb/web/generated/projects/20260926-story-ap48e14c3b9d--explainer_video/versions/20260926-story-ap48e14c3b9d--explainer_video-v2.json:25)把“分钟国风、水墨、视频”当作缺失人物。[findAdaptationIssues](/Users/wuyu/Desktop/china-culture-kb/web/server/src/services/genre-quality-service.ts:117)在core_characters为空时从original_user_query猜名字。

范围：沿现有素材解析/改编分析合同区分“真实原作材料”和“时长、画幅、声音、风格等制作要求”；质量检测使用可追踪素材，不能把格式要求抽为人物。不要只增加几个停用词，也不要直接关闭改编校验。

验收：

- 先用该真实需求建立能复现误判的红测。
- 制作要求不再产生伪人物；确有原作人物时，遗漏人物/关键节拍仍能被检出。
- 无原作文本、材料为空、未知来源采用明确的无可比较/待补状态，不伪造人物或事实。
- 不自动将整份v2质量报告改为通过；其余真实内容缺口保留。
- 只做局部代码与定向验证，不调用LLM、TTS、ImageGen或GPU，不改样片和生成项目版本。

### S02：已有媒体正式导入并接通UI视频入口（GEARS）

提供明确的existing-media导入应用服务/API与UI：绑定真实项目/草稿、文件、实际SHA-256、图片格式和来源；形成可被现有视频选择器使用的合法输出引用。

保留ImageGen/external-import来源，不把旧图伪标成GEARS新生成、正式人物基准或人工签收。复用既有媒体/项目合同，先核对StoryboardOutput语义，再决定是否需显式外部导入输出类型。

验收：真实文件导入可回读与选择；幂等重放不重复建项；同键异内容、跨项目、越界路径、格式/哈希错误被拒绝；无LLM/生图/视频提供方调用。先使用临时库和fixture，真实7图导入需明确目标与回滚方案。

### S03：动作保真与参考图适配（KB合同 + GEARS消费）

优先扩展现有Production Board/preproduction/GEARS单元，不新造第三套大框架。以下是建议合同语义，不是声称已有字段：

- 每镜有独立旁白/对白、可见动作与关键节拍；旁白不是动作提示词，动作描述不是字幕。
- 记录起始状态、动作、结果状态、必须兑现的动作及来源场景/单元。
- 参考图记录其实际状态；如果图已是“帮助之后”，不能假装它能覆盖“遇阻→上前”。
- 无法表达时给出拆镜、补参考图、换执行能力等明确方案；不能静默删掉关键动作来保稳定。
- 修复social_short逐场重复旁白、同场拆镜复用整场动作的问题；先对当前代码复现，不从手工修好的了凡样片倒推这些已消失。
- 对齐请求时长、场景时长、素材生成时长和剪辑使用时长；使用帧数/余数分配保证守恒，不靠均值四舍五入或截断。

验收基准：书桌开场、改过动作、扶车动作三组即可。必需动作在导出与导入后仍可追踪；缺失资产/能力会显式阻断或要求选择；本地fallback与外部模型路径遵守同一合同。

### S04：同镜头连续生成、接缝预览与局部返修（GEARS）

每个边界明确是“连续动作”还是“有意切镜”。连续动作只有在适配器确有能力时使用前段末帧/状态作为后段输入；不支持则设计合法的不同景别或插入镜头，不再默认同图A/B/C能自然接续。

保留输入图/终帧/提示词/视频hash与前后关系。提供接缝前后短预览和异常标记，返修只重做失败段，失效相关拼接/审核，保留确认音轨。

验收：故意重置的fixture必须被提示；有意切镜不被误报成续接失败。接缝检查不能仅靠单帧差异或hash证明叙事连续，也不能用循环、冻帧或无条件交叉淡化掩盖问题。

### S05：把已验证的声音与时间轴流程产品化（GEARS执行；KB记录合同/回执）

已有样片证明“试听→确认→全片→语音边界字幕”可用，优先复用，而不是另换整套声音方案：

- 保存音色、语速、停顿/情绪参数、试听及确认版本；项目级保留批准素材。
- 统一保存语音边界、字幕、章节、画面使用长度、BGM混音与总帧数。
- 图片/视频局部返修不触发全片重新配音，不切断整条人声。
- 单片/系列共享GEARS后期执行能力；KB不承担新的FFmpeg实产实现。
- 横竖屏是明确制作配置；竖屏需要重新构图与字幕安全区，不默认把横屏直接裁切。

验收：字幕只取实际对白/旁白，全文覆盖、不重叠、不混入动作；配音未被时长调整；标题与段落同步；源分辨率和输出分辨率分别展示；技术测试不冒充完整主观试听。

### S06：模型能力配置与受控对照（GEARS）
