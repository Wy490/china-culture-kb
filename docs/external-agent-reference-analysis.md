## 3. 对当前 Agent 的帮助

### 3.1 山音编剧工作流能补什么

当前系统已经有知识库、叙事流派、故事生成、小说改编和 GEARS 供稿能力，但用户反馈中暴露出一个核心问题：故事生成容易在“故事摘要”层停住，剧本单元正文不够饱满。

山音工作流可补强：

- 从大纲到剧本的层级化拆解：创意、人物、冲突、结构、场景、正文。
- 场景必须具备地点、动作、冲突、情绪、转折，而不是空泛总结。
- 短剧和 AI 漫剧需要可视化、可拍摄、可生成的场景单元。
- 对小说改编，重点不是重写故事，而是保留人物关系、因果顺序、主题和情绪底盘。

建议接入点：

- 故事生成 Prompt 的“剧本正文要求”。
- AI 漫剧单集生成的“场景正文密度”。
- 质量校验中的“场景是否有行动、冲突、转折、可视画面”。
- 一键修复中的“把摘要型场景扩写为剧本型场景”。

### 3.2 Toonflow 工作流能补什么

Toonflow 的价值不在文风，而在流程架构。它把创作拆成脚本 Agent 和生产 Agent：前者处理素材、事件、剧本计划，后者处理资产、导演计划、分镜和监督。

这正好对应当前产品的下一步：

- 用户不只要故事，还要能进入 GEARS、AI 漫剧、视频模型的生产链路。
- 需要把“剧本内容”和“画面生成提示词”分离。
- 需要维护角色、场景、道具、服饰、镜头、连续性等生产资产。
- 需要监督检查：缺资产、画面不可生成、分镜太空、人物服饰跑偏、提示词含杂质。

建议接入点：

- 新增 Production Board 数据结构。
- GEARS 供稿从段落级升级到镜头 / 分镜级。
- 增加角色资产、场景资产、道具资产、服饰资产的派生和复用。
- 增加分镜监督器：检查每个镜头是否可生成、是否有主体、动作、环境、时代约束、连续性约束。

## 5. 仍需重点优化的问题

### 5.1 用户大纲遵循仍要做成硬约束

用户输入大纲时，Agent 必须先抽取大纲节点，并在生成后逐项对齐：

- 每个大纲节点是否出现。
- 是否按原顺序推进。
- 是否新增了未授权主线。
- 是否跳到了大纲之外的时代、地点、事件。
- 是否把知识库检索内容错误插入为正文主线。

建议新增“Outline Coverage Report”：

- 节点覆盖率。
- 偏移节点。
- 缺失节点。
- 非授权新增事件。
- 自动修复建议。

### 5.2 流派质量信号要从弱提示升级为可解释检查

现在“流派质量信号偏弱”会告诉用户哪里弱，但没有给出足够明确的修复路径。

应改成：

- 已满足信号。
- 偏弱信号。
- 具体缺口。
- 为什么影响成片。
- 建议补哪类场景。
- 可一键修复的 Prompt。

例如武侠不能只有“武侠”：

- 侠义史诗：江湖道义、公共危机、牺牲选择。
- 古龙式孤刀谜案机制：冷开场、孤独主角、谜案推进、对白锋利、反转揭示。注意只抽象机制，不复制作者文风。
- 金庸式家国成长机制：门派、师承、家国秩序、成长代价、群像关系。注意只抽象机制，不复制具体人物和情节。
- 门派成长：师承规则、试炼、同门竞争、武学代价。
- 庙堂江湖：朝堂权力与江湖伦理互相牵引。

其他大类也应同样拆细：

- 悬疑：本格解谜、社会派、心理悬疑、密室、反转短剧、民俗悬疑。
- 历史：人物传记、时代切片、制度变迁、战争抉择、地方志故事。
- 仙侠：凡人修行、宗门权谋、天命反抗、情劫宿命、神魔战争。
- 言情：先婚后爱、破镜重圆、双强博弈、暗恋成长、虐恋救赎。
- 短剧：复仇爽点、身份反转、情绪拉扯、强钩子连续反转。

### 5.3 小说改编模式要和原创故事彻底分流

用户自己有小说时，不需要 Agent 重新生成小说故事。系统应该进入“改编模式”：

- 先做原作解析，不直接改写。
- 提取人物、关系、章节、事件链、情绪线、世界观规则。
- 让用户选择改编目标：漫剧、短剧、动画、分镜、Seedance 视频提示词。
- 生成改编策略：保留什么、压缩什么、前置什么、合并什么、拆分什么。
- 输出分集 / 分场 / 分镜，而不是另起炉灶写新故事。

### 5.4 GEARS 供稿要升级为生产资产包

当前问题包括：

- 人物服饰设定可能跑到错误朝代。
- 场景描述含杂质，不能直接用于生成场景图。
- 剧本单元正文太薄，无法支撑剧情。
- 角色、场景、道具没有稳定复用标识。
- 镜头级信息不足。

建议 GEARS 包拆成：

- `character_assets`
- `costume_assets`
- `location_assets`
- `prop_assets`
- `shot_units`
- `prompt_units`
- `continuity_constraints`
- `negative_constraints`
- `qa_report`

每个镜头必须有：

- 主体。
- 动作。
- 场景空间。
- 时代 / 服饰约束。
- 情绪。
- 镜头类型。
- 生成提示词。
- 禁止项。

## 6. 下一阶段开发计划

### P0：把质量问题变成可修复工作流

目标：用户看到的不只是“偏弱”，而是“怎么改、点哪里改、改完会怎样”。

开发项：

- 新增 Outline Coverage Report。
- 新增 Pattern Quality Report。
- 新增 GEARS Readiness Report。
- 在前端展示：
  - 已满足项
  - 风险项
  - 一键修复建议
  - 修复后预览
- 后端增加修复 Prompt Builder：
  - 修复大纲漂移
  - 修复流派信号弱
  - 修复剧本正文单薄
  - 修复 GEARS 提示词杂质

### P1：生产流程升级

目标：从“故事生成器”升级为“故事到成片生产工作台”。

开发项：

- 新增 Production Board 数据结构。
- 从故事结果派生：
  - 角色资产
  - 场景资产
  - 道具资产
  - 服饰资产
  - 镜头 / 分镜表
- 增加 Director Plan：
  - 每场戏的戏剧目的
  - 情绪转折
  - 镜头逻辑
  - 转场逻辑
- 增加 Supervision Agent：
  - 检查时代错配
  - 检查资产缺失
  - 检查提示词不可生成
  - 检查角色连续性

### P1：小说改编工作台完善

目标：用户上传或粘贴自己的小说后，系统不再生成新故事，而是做专业改编。

开发项：

- 小说解析：
  - 章节切分
  - 人物关系图
  - 事件链
  - 情绪线
  - 世界观规则
- 改编策略选择：
  - 忠实改编
  - 漫剧节奏改编
  - 短剧强钩子改编
  - 分镜优先改编
- 输出：
  - 分集大纲
  - 单集剧本
  - 分镜表
  - GEARS 供稿
  - Seedance 镜头提示词

### P2：流派库继续扩充

目标：让用户选到真正贴合项目气质的机制，而不是粗粒度类型。

开发项：

- 武侠矩阵继续细化。
- 悬疑矩阵。
- 历史剧矩阵。
- 仙侠矩阵。
- 言情矩阵。
- 都市 / 现实题材矩阵。
- 短剧爽点矩阵。
- 儿童 / 教育内容矩阵。

每个流派包都应包含：

- 适合的成片类型。
- 主角引擎。
- 冲突引擎。
- 节奏模式。
- 必备场景配方。
- 质量信号。
- 避免项。
- 可视化资产倾向。
- 修复建议模板。

### P2：视频模型导出

目标：把故事和分镜转成不同视频模型可用的提示词包。

开发项：

- Seedance Prompt Export。
- Higgsfield Prompt Export。
- GEARS JSON Export。
- 镜头级提示词。
- 角色一致性参考图字段。
- 场景一致性参考图字段。
- 负面约束。
