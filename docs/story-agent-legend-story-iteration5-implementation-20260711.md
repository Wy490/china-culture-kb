# Story Agent `legend_story` Iteration 5 实现报告

更新时间：2026-07-11

状态：legend_story_internal_contract_ready_real_model_and_human_validation_pending

## 本轮结论

`legend_story` 已建立不侵入现有生成主链的专业文本候选管线。它从显式传入的故事、研究证据和传说专业证据生成 `ProfessionalTextPackage`，以版本边界、神异元素功能、凡人考验、主动选择与后果、重复象征意象、口述节奏及逐场传说/改编边界作为硬门槛。

本轮没有调用真实模型，没有把文学文本、地方口述、现实地名或传说遗迹反向证明为神异事件史实，也没有把 fixture、simulation、机器评分或合法 schema 计为专业通过。

## 已实现

1. `professional-legend-story-pipeline-service.ts`
   - 只接受 `legend_story`，仅通过显式调用启用。
   - 填充创作简报、证据包、版本/改编合同、人物关系、传说节拍、分场、完整正文、口述文本、导演文本、连续性台账和交付文本。
   - 不修改 `story-service.ts`、现有 prompt、fallback 或前端生成入口。
2. `professional-legend-story-quality-service.ts`
   - 执行十维候选评估，`professional_passed` 固定为 `false`。
   - 建立 12 项硬门槛：简报、完整成稿、至少两个不同层级版本、神异功能、凡人目标/考验、选择与后果、象征意象、至少三场意象重复、逐场行动/转折、口述节奏、逐场传说边界、总体事实/传说/改编/未知边界。
3. `professional-legend-story-revision-service.ts`
   - 将版本与事实问题分流到人工证据补充，将人物、节奏和意象问题分流到模型重写。
   - 分场变化后可确定性重建节拍、导演文本和交付单元，并写入 `revision_trace`。
4. 固定项目规格
   - 屈原端午传说、炎帝神农、湘妃竹、刘海砍樵、柳毅传书，共 5 项。
   - 每项冻结凡人考验、象征意象和版本关注点，状态均为 `awaiting_real_model_run`。
5. 失败 fixture
   - 将文学、口述与地方改编压成唯一史实版本。
   - 只有神异奇观，没有凡人目标、考验、选择与后果。
   - 缺少重复意象、口述节奏、逐场变化和版本边界。
   - 三类 fixture 均触发登记门槛，只用于结构回归。
