# 中国文化知识库内容扩充长期计划（2026-07-13）

## 1. 计划定位

本计划解决的不是工具链是否存在，而是 Story Agent 在实际创作时可检索、可改编、可分镜的知识供给不足。

现有 `knowledge-base-long-term-development-status` 的 99% 主要代表审稿、候选、Domain Pack、写回和安全门禁已经产品化，不能解释为内容规模、全国覆盖或片型素材密度达到 99%。从本计划开始，必须把以下两条进度分开：

```text
知识库治理与生产流程成熟度 ≠ 知识库内容供给成熟度
```

本路线只统计真实进入知识库、来源清楚、结构完整并通过审查的内容；候选清单、机器补全、fixture、simulation、模板和未审稿草案不计正式内容完成。

## 3. 长期北极星

建设一个能稳定支撑 15 个 Story Agent `VideoType` 的文化知识生产系统：

```text
可信来源与原子知识
  → 人物 / 事件 / 地点 / 工艺 / 民俗资产
  → 可复用 Domain Pack
  → 片型生产素材卡
  → StoryBlueprint
  → full_text / scene_breakdown / gears_segments
  → 质量审计与项目反馈
  → 已审稿的可复用知识写回
```

长期验收能力：

1. 可检索：用户提出地区、题材、人物、时代、片型和视觉需求时能召回足够材料。
2. 可创作：条目包含目标、压力、选择、行动、后果和文化细节，不只是百科摘要。
3. 可分镜：具备地点、时间、人物动作、道具、服饰、声音、视觉符号和连续性锚点。
4. 可交付：能支持脚本、分场、GEARS segment 和 Seedance 提示词，但不把生成结果写成知识事实。
5. 可追责：硬事实、传说、口述、合理戏剧化和虚构都有明确来源与边界。
6. 可维护：省份底库、Domain Pack、生产素材卡和项目素材包职责分离。

## 4. 内容供给进度模型

新增独立的 `knowledge_base_content_supply_progress`，不要继续使用治理路线的 99% 表示内容充足度。

| 维度 | 权重 | 完成标准 |
|---|---:|---|
| 全国地域覆盖 | 20% | 34 个地区均达到分阶段条目配额 |
| 题材与时代覆盖 | 15% | 核心题材、时代和生活层级没有结构性空白 |
| 来源与事实边界 | 20% | 来源、claim 绑定、核实方法和改编边界达标 |
| 创作生产字段 | 20% | 可见动作、冲突、场景、道具、声音和禁用表达完整 |
| 15 片型生产素材卡 | 15% | 每片型达到配额并通过片型门禁 |
| Domain Pack 与黄金资产 | 5% | 高复用包和黄金卡真实审稿通过 |
| 检索与生成效果 | 5% | 固定查询召回和下游故事质量提升得到验证 |

以下内容不计完成：

- 只有标题的候选条目。
- 没有来源的机器生成介绍。
- 仅有链接、没有 claim 绑定的来源堆积。
- 未审稿的自动补全生产字段。
- 由故事成稿反向推断出的“事实”。
- fixture、simulation、fallback、prepared 和 readiness。

## 5. 内容分层与存放边界

### 5.1 省份底库

位置：`data/provinces/*.md`。

只存：

- 具体人物、事件、地点、非遗、民俗、饮食、文学、艺术和生活文化条目。
- 来源、可信度、核实方法、待核点、事实边界和基础创作资产。

不存：

- 生成故事正文。
- 项目专属分镜或提示词。
- 未审稿的用户补充内容。
- 跨条目通用规则的重复副本。

### 5.2 Domain Pack

位置：`data/domain-packs/`。

存放跨条目复用内容：

- 朝代服饰、称谓、器物和空间。
- 非遗材料、工具、工序与传承模式。
- 纪录片来源结构与再现边界。
- AI 漫剧分镜、反应格和连续性规则。
- 儿童改写安全、讲解结构和短视频钩子规则。

### 5.3 片型生产模板

位置：`data/production-packs/video-type-material-supplement-packs.json`。

只定义片型 required fields、prompt layer、gate、补充问题和示例，不存具体人物传记。

### 5.4 条目级生产素材卡

位置：`data/production-cards/` 及既有候选/审稿体系。

索引至少包含：

```text
entry_name + province + video_type
```

生产素材卡保存片型特有字段、来源引用、审稿状态和写回状态，不把所有片型字段塞回省份 Markdown。

### 5.5 项目素材包

位置：`web/generated/projects/*/project.json`。

项目故事、分场、提示词和交付状态默认留在项目层。只有跨项目复用、来源清楚、完成人审的材料才进入写回队列。

## 8. 单条知识的标准合同

### 8.1 身份字段

- 名称、省份、地区、类型、时代。
- `knowledge_domain`、`entry_role`、`asset_usage`。
- 关键词、别名、相关人物、相关地点和时间锚点。

### 8.2 证据字段

- 已确认事实。
- 待核事实与版本差异。
- 来源列表及 A/B/C/D 等级。
- claim 与来源对应关系。
- 核实方法、核实日期和需要人工确认的部分。
- 版权、肖像、社区授权或现实拍摄限制。

### 8.3 创作字段

- 人物目标、压力、选择和后果。
- 关系冲突或知识发现过程。
- 可戏剧化空间。
- 明确虚构空间。
- 禁止写成事实的表达。
- 可见动作、场景、道具、服饰、陈设和视觉符号。
- 环境声、音乐或口述节奏线索。
- 对白/旁白口吻。
- 当代遗存和现代连接。

### 8.4 片型字段

- 推荐 `VideoType`，至少 2 个。
- 每个推荐片型的用途和不适用边界。
- 可生成的 StoryBlueprint 核心问题。
- 可拍场景与不可拍/待授权资产。
- 片型专属补充问题。

### 8.5 原子性要求

一个条目只描述一个主要文化资产。以下内容应拆分：

- 人物传记与服饰规则。
- 地方故事与通用志异母题。
- 单一遗址与跨地区场景资产。
- 具体非遗项目与通用工艺流程。
- 历史事实与后世文学改编。

## 9. 来源与可信度政策

### 9.1 来源等级

- A：一手文献、档案、考古报告、本人著作、正式法规和原始记录。
- B：博物馆、文保单位、非遗保护机构、地方志、政府或国际组织正式资料。
- C：学术专著、核心论文、专业工具书和权威二手研究。
- D：旅游讲述、媒体转述、民间口述、戏曲改编和未定位原始出处的公开内容。

### 9.2 新条目最低门槛

- 至少 3 个来源。
- 至少 1 个 A 或 B 级来源。
- 至少 2 个相互独立的来源主体。
- 聚合百科和旅游宣传不能作为唯一事实来源。
- 每个关键事实必须能定位到来源，不只保存一个 URL 列表。
- 长引用只保存短摘录和定位信息，避免复制受版权保护的完整文章。

### 9.3 事实边界

每条内容必须区分：

```text
已核事实
合理戏剧化
明确虚构
传说/口述版本
未知或禁止断言
```

文学原典能证明某种叙事传统存在，不自动证明其内容是历史事实。

## 10. 15 片型内容扩充策略

### 10.1 第一优先级：最缺且复用面最大

1. AI 漫剧：先做 20 张。
   - 开场钩子、对手压力、关系碰撞、对白气泡、反应动作、情绪节拍、关键帧、连续性和结尾钩子。
2. 微纪录片：先做 20 张。
   - 纪录问题、现实人物、采访角色、现场观察、B-roll、环境声、当代遗存和再现边界。
3. 知识讲解：先做 20 张。
   - 核心问题、概念、知识层级、具体例子、视觉比喻、图示字幕、误区和总结。

### 10.2 第二优先级

- 非遗宣传：材料、工具、工序、手部动作、传承关系、现实压力。
- 社交短视频：前三秒事实钩子、持续新信息、竖屏动作、字幕与互动收束。
- 教育培训：学习目标、步骤、示范、练习、评估和反馈。
- 宣讲片：立论、证据、案例、反方、回应和行动结论。
- 儿童故事：年龄、温和冲突、尝试因果、情绪学习和亲师提示。

### 10.3 第三优先级

- 人物故事、历史剧、传说、文化宣传、城市品牌、场景短片和风光意境。
- 这些片型已有较完整的内部合同，但仍需全国化素材和真实样本。

长期目标：15 个片型每类至少 50 张已审稿生产素材卡；高频 8 片型先达到每类 20 张。

## 11. Domain Pack 建设计划

优先真实审稿并晋升现有 8 类：

1. 非遗流程包。
2. 纪录片来源包。
3. AI 漫剧分镜包。
4. 朝代服饰与器物包。
5. 知识讲解结构包。
6. 短视频钩子包。
7. 儿童改写安全包。
8. 宣讲/培训结构包。

每个正式 Domain Pack 必须：

- 覆盖至少 5 个真实高优先级条目。
- 有 trigger、适用范围、资产用途和禁止范围。
- 有来源或明确声明其为创作规则。
- 通过真人审稿、重复项审查和下游调用验证。
- 不把 pack 摘要写成具体人物或事件事实。

## 12. 长期路线图

### 12.1 第 0 阶段：重新建立内容供给基线（1 周）

- 新增内容供给进度报告，与治理 99% 分离。
- 冻结 34 地区、当前条目数、题材、时代、片型 readiness 和缺失字段。
- 建立确定性候选队列和重复项检查。
- 不新增自动写回权限。

退出条件：所有后续批次都能回答“补了哪个缺口、从什么基线增长、是否已经审稿”。

### 12.2 第 1 阶段：全国最低覆盖 M1（2—4 周）

- 新增 23 条，使 34 个地区全部至少 2 条。
- 同步修复生产评分低于 80 的 25 条旧条目。
- 新条目生产评分目标不低于 90。

退出条件：34/34 地区有正式条目，新增条目来源与边界全部通过。

### 12.3 第 2 阶段：全国基础覆盖 M2（2—3 个月）

- 再新增 97 条，使每地区至少 5 条。
- 湖南以质量治理为主，不再占用扩量主配额。
- 补完现有 119 项对白口吻、87 项戏剧化空间、45 项禁用表达和 8 项视觉符号缺口。

退出条件：正式条目达到 289 条以上，34/34 地区至少 5 条，湖南占比降至约 43%。

### 12.4 第 3 阶段：片型生产矩阵（3—6 个月）

- 完成 AI 漫剧、微纪录和知识讲解各 20 张，首批共 60 张。
- 再完成其余 5 个高频片型各 20 张，累计 160 张。
- 每批使用固定查询和固定 Story Agent 合同验证下游增益。

退出条件：8 个高频片型均有不少于 20 张已审稿素材卡，低于 60 的推荐 readiness 显著减少。

### 12.5 第 4 阶段：全国可创作覆盖 M3（6—12 个月）

- 正式条目达到 450 条以上。
- 每地区至少 10 条并形成跨条目关系网络。
- 重点补日常生活、饮食、女性与普通人、声音、地方戏曲、当代传承和现代城市文化。
- 现有 8 个 Domain Pack 完成真实审稿和调用验证。

退出条件：常见地区 × 题材 × 片型查询不再依赖湖南条目兜底。

### 12.6 第 5 阶段：稳定供给 M4（12—24 个月）

- 正式原子条目达到约 800 条。
- 15 个片型每类至少 50 张生产素材卡。
- 建立 100 个固定检索/生成回归查询。
- 建立不少于 200 张已审稿黄金素材卡。
- 项目反馈按季度形成真实写回批次。

退出条件：知识库能持续支持全国、多题材、多片型创作，并能用固定回归证明扩库确实提升召回、事实边界和故事质量。

## 13. 每批内容工作流

```text
缺口队列
  → 候选题目与去重
  → 来源搜集与分级
  → claim/source 对应
  → 原子知识条目
  → 事实/戏剧化/虚构边界
  → 创作生产字段
  → 片型适配
  → 机器 lint / audit
  → 人工来源与文化审稿
  → 正式 Patch
  → 固定查询与生成回归
```

禁止从“先生成一篇故事”开始反向拼知识；应先形成可审计知识，再进入 StoryBlueprint 和成稿。

## 14. 批次大小与周节奏

默认单周产能：

- 新增正式候选条目 10 条。
- 修复旧条目 15 条。
- 新增片型生产素材卡 5 张。
- 完成 1 次来源、重复项和事实边界复核。
- 完成 1 次固定检索/生成回归。

批次建议：

- 研究批：5 条，便于同源资料复用但不混淆 claim。
- 写入批：不超过 10 条，便于逐文件复核。
- 人工审稿批：5—8 条。
- Province Markdown Patch：一次只处理一个地区或一个高度关联主题。

## 15. 自动化与验证

每个正式批次至少运行：

```bash
cd mcp-server
npm run kb:normalize-credibility
npm run kb:enrich-machine-metadata
npm run kb:asset-split-suggestions
npm run kb:production-audit
npm run kb:production-upgrade-plan
npm run kb:lint
```

执行前后都必须检查 diff；自动化只允许规范化、补机器元数据和生成报告，不能把机器判断自动变成人工审稿结论。

新建或修改条目的验收：

- Markdown 结构和枚举通过 lint。
- 来源不少于 3 个且等级合规。
- 来源、地点、核实方法不缺失。
- 生产评分不低于 90；特殊高价值条目若暂未达到，必须进入 repair 队列。
- 无重复条目、重复标题或复合资产未拆分问题。
- 明确推荐片型和禁用边界。
- 固定检索能找到该条目。
- Story Agent 可构建 StoryBlueprint，但生成故事不得写回底库。

## 16. 检索与下游效果验收

扩库不能只看条目数。建立以下固定查询集：

- 地区 + 人物 + 抉择。
- 地区 + 历史事件 + 可见行动。
- 非遗 + 工序 + 手部动作。
- 民俗 + 当代现场 + 事实边界。
- 传说 + 原始文本 + 版本差异。
- 城市 + 空间路线 + 在地生活。
- 儿童 + 温和冲突 + 安全边界。
- 纪录片 + 现实人物 + B-roll。
- 讲解 + 核心问题 + 误区。
- AI 漫剧 + 关系碰撞 + 连续性。

每批比较：

- Top-K 召回是否命中正确条目。
- 是否错误跨省、跨时代或混淆同名人物。
- StoryBlueprint 是否引用足够事实与可见动作。
- 是否减少空泛赞美、百科摘要和虚构史实。
- scene_breakdown 与 gears_segments 是否获得更具体的地点、道具、动作和声音。

## 17. 角色与人工责任

长期协作至少需要：

- 内容研究：候选与来源定位。
- 事实/文化审稿：确认 claim、版本和禁用边界。
- 类型编辑：检查素材是否真正服务片型。
- 数据维护：原子拆分、去重、元数据与 Patch。
- 回归验收：检索、StoryBlueprint、成稿和交付结构检查。

同一人可兼任，但高风险历史、民族宗教、现实传承人和儿童内容应有独立复核。

## 18. 风险与防护

1. 数量虚高：禁止只有标题、简介和链接的薄条目。
2. 湖南继续失衡：湖南新增量需单独审批，默认优先其他 33 地区。
3. 来源污染：聚合百科不能成为唯一来源；旅游口径必须标级。
4. 传说史实化：文学和口述只能证明叙事传统，不能自动证明事件真实。
5. 版权污染：不保存长篇受版权保护正文、完整剧本或未授权图片。
6. 复合条目膨胀：人物、事件、服饰、场景和母题按原子资产拆分。
7. 机器审稿冒充人工：机器评分只用于队列排序，不能授予黄金或正式通过。
8. 生成内容回流：故事、对白和分镜默认属于项目，不得直接成为知识事实。
9. 敏感内容误用：民族、宗教、战争创伤和现实个人材料需要更高来源与授权门槛。
